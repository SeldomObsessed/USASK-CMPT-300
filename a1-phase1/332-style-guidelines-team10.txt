***** Braces and Indentation *****

Allman style eg.
if (x) 
{
  ...
}


  Indentation style: 2 spaces


Continued lines will be aligned and indented...:

int do_something_with_data(
  int first_arg,
  int second_arg,
  int third_arg,
  int fourth_arg);

They may also have longer lines before being continued, lines also need to
be split at sensible places (i.e. operators) :

if (very_long_expression && another_long_expression &&
  yet_another_long_expression && final_expression)
{
  ...
}


***** Naming Conventions *****

  Variable and functions: snake_case

  Constants/macros: SCREAMING_SNAKE_CASE

  Structs, enums: snake_case

  Typedefs: CamelCase

  Filenames: lowercase-separated-by-dashes.txt (or whatever Makaroff seems to
             specify)

***** Commenting Style *****

  Block / inline comments: /* .... */            

  Header comments: Follow "File Team Names" conventions, below "CMPT 332 Fall
                   2025" an optional description and notes may be added. The
                   description is all lowercase unless multiple sentences long
                   and the notes start with "-". e.g.

/*
 * complexComp.c
 * Logan Fossenier & William Morris
 * hzv143 & wjm625
 * 11343891 & 11278140
 * CMPT332 Fall 2025
 *
 * this file implements functions for handling complex numbers, including
 * addition, subtraction, multiplication, and division
 *
 * - uses double precision for calculations
 * - error checking is minimal; caller is responsible for input validation.
 */


  Function comments: Will optionally contain a description of purpose,
                     explanation of functionality, description of params, and
                     description of returns. e.g.

/*
 * compares two complex numbers to determine which is larger
 *
 * only accepts strings with the real and imaginary components being written
 * as two space separated doubles
 *
 * void *first: a string of the first number to be compared
 * void *second: a string of the second number to be compared
 *
 * returns -1 if first < second
 * returns 1 if first > second
 * returns 0 if first == second
 */

***** Code Layout *****

    Line length: 80 Character limit *For all filetypes*

    Blank Lines: No blank lines after variable declarations, but 2 between
                 functions.
    
    Grouping: In order: includes, globals, function defs eg.

#include <stdio.h>
#include <stdlib.h>

#include "mymodule.h"

/* Global variables */
static int counter = 0;

/* Function definitions */
void do_something(void) {
    counter++;
    helper();
}

static void helper(void) {
    printf("Helper called!\n");
}


            Global Variables: _____________ are we allowed to use these logan?

            Parameter passing: By pointer, reference and value, when needed/

            Magic numbers: FORBIDDEN

**** Error Handling ****

            Return codes: standard approach eg 0 = success, nonzero = error

            Assertions: Assertions will be used only to validate programmer 
                        assumptions eg.
       
assert(ptr != NULL); /* We promised this function never gets NULL */
        
            Error: Expected runtime errors must be handled with error messages
                   and proper return codes eg.

variable = malloc(sizeof(structure))
if (variable == NULL)
{
    fprintf(stderr, "Error: malloc failed\n);
    return -1;        
}

**** Preprocessor Directives ****
            
            Include guards: #ifndef FILE_H #endif
    
            Order of includes: stdlib first, then project headers
